# Параматрица — решения по вопросам Implementation Plan 0.1

Журнал решений пользователя по вопросам из `IP_0_1_Implementation_Plan.md` (Часть I).
После завершения разбора решения вносятся в план.

## Р0. Сквозной принцип: явная ошибка вместо подстраховки

Если что-то не работает, игра явно сообщает об ошибке. Неработающие сценарии не пропускаются, не перезапускаются,
не заменяются поведением «по умолчанию»: это скрывает проблему. Упор — на точность исполнения.

Все выборы вида «строгая ошибка / мягкий обход» решаются по этому принципу без отдельного согласования.

## Р1 (A1). Память о пройденных сценах и сюжетные факты

- Условия (Conditions) не проверяют статус сцен (Events) напрямую. Они проверяют только факты в State.
- Сцена, которая устанавливает сюжетно значимый факт, ставит его явно Action `set_state`.
- Факт хранится у сущности, к которой он относится по смыслу (свойство двери — у двери, встреча — у героя или у story-сущности).
- Постоянные факты не удаляются и не сбрасываются.
- Одноразовые «новости» (то, что герой должен донести) — отдельные свойства; их сбрасывает сцена, которая их использовала. Автоматической передачи фактов между персонажами нет.
- История выполнения сцен (once, once_per_location_visit) — внутреннее состояние Scenario System; сохраняется собственным снимком Scenario. Save = снимок State + снимок Scenario (уточнение 0.3.1 §9).

## Р2 (A2). Начало новой игры и загрузка

- New Game: после инициализации всех систем, включая Scenario, Game Flow выполняет обычный вход в стартовую локацию: начинается Visit #1, публикуется `LocationEntered`. Вступление — обычная сцена на `LocationEntered` с Launch Condition.
- Load Game: Restore State и Scenario, локация загружается технически, `LocationEntered` нет, новый Visit не начинается.
- Меняет порядок шагов 0.3.1 §7 (вход в стартовую локацию — после шага 12).

## Р3 (A3). Сцена, завершившаяся ошибкой

- Failed-сцена заблокирована: новые triggers её не запускают до загрузки сохранения.
- Статус Failed не сохраняется в снимок Scenario; после Load сцена снова доступна (с учётом её Repeat Policy).
- Автоматического повтора нет; запросы этой сцены в очереди удаляются.
- Уже применённые изменения State не откатываются (Addendum §3).
- Следствие для Gameplay Systems: штатные игровые помехи (путь перегорожен и т.п.) не должны возвращать Failure — их система обрабатывает сама (ждёт, обходит). Failure — только настоящая ошибка, иначе случайность блокирует сцену до загрузки.

## Р4 (A4). CALL и START недоступной сцены

- CALL и START проверяют у целевой сцены: не Running, не Failed, Repeat Policy, Launch Conditions.
- Любая проверка не пройдена (включая Launch Conditions = False) — Failure вызывающей сцены. Пропусков нет.
- Если вызов допустим не всегда, сценарист явно оборачивает его в `if`.

## Решения по принципу Р0 и по минимальности (без отдельного вопроса; возражения — до внесения в план)

- **A10. Один trigger — несколько сцен.** Кандидаты обрабатываются в порядке Event ID.
  Автоматический trigger: допустимые Exclusive встают в очередь в этом порядке (несколько сцен на «вход в офис» — нормально).
  Действие игрока: если допустимы две и более Exclusive — Error, не запускается ни одна. Validator предупреждает о пересечениях заранее.
- **A15. Save не совпадает с контентом** (удалено свойство, сменился тип, вышло за диапазон) — Load отклоняется целиком с ошибкой, мир не меняется. Миграции — вне MVP.
- **Предохранитель цепочек** (сцены бесконечно запускают друг друга) — Error, каскад останавливается.
- **Монитор ConditionsMet**, условие которого вычисляется с ошибкой, — Error diagnostic; срабатывания нет.
- **A9. `reconstructible`** — убирается из MVP: у него нет ни одного потребителя и нет правила восстановления. Остаются `persistent` и `transient`.
- **A11. Trigger types.** В MVP: Interaction, ItemAcquired, ItemUsed, ItemCombined, StateChanged, LocationEntered, DialogueCompleted, EventCompleted, ConditionsMet. PlayerAction, DialogueStarted, AnimationCompleted не реализуются, пока не определены; ссылка на них в контенте — ошибка Validator.
- **A16. Ссылка на сущность в State** (например, текущая локация) — Enum со значениями-ID; значение, не являющееся существующим ID, — ошибка Validator.

## Р5 (A12, A13, A14). Исходные данные

- Architecture 0.3 сохранена как `A_0_3.md` (сводка обсуждений; Game Flow, Dialogue, Location, Inventory, Interaction). План охватывает и эти системы.
- Зависимость `com.unity.nuget.newtonsoft-json` разрешена.
- Платформа: только Windows 10 и выше. Контент читается синхронно.

## Р6. Реакции на взаимодействия (0.3 §2.5, §5.6)

- Простые реакции — отдельный вид контента `response.*`: реплика без действий, не сцена.
- Порядок разрешения действия игрока: сначала сцены (Events), подходящие под действие; если ни одной — реакции по уровням specific → contextual → generic → fallback.
- Две и более подходящих сцены или две и более реакции одного уровня specific/contextual — Error (Р0).
- Generic — пул: реакции идут по кругу, одна и та же не повторяется подряд; пул из одной реакции — ошибка Validator.
- Fallback — ровно одна на каждый тип взаимодействия (Validator). «Нет реакции» допускается только явным объявлением.
- Реакцию, которой нужны действия (анимация и т.п.), оформляют сценой.

## Р7. Взять предмет, выйти из локации — только сценой

- Перемещение предмета (взять, отдать, израсходовать) и переход между локациями выполняются только Actions сцены. Inventory и Location System исполняют команды, сами решений не принимают.
- Нет сцены для действия — работает реакция (Р6), обычно fallback.

## Р8. Вид игры

- 2D, вид сбоку.

## Р9. Позиция героя после загрузки

- После Load герой появляется на точке входа локации по умолчанию. Позиция героя не сохраняется.

## Р10. Три режима диалога (2026-11-10; меняет 0.3 §2.2–2.5)

| Режим | В контенте | Время | Управление | Сцены |
|---|---|---|---|---|
| Монолог | не диалог: реакция `response` на клик или действие сцены `say` (`minimal` в диалоге — ошибка) | идёт | у игрока | сцена может запустить (`say`), но не ждёт |
| Обычный | `normal` | стоит (`WorldPause`) | заблокировано | сцена ждёт конца диалога |
| Новелла | `novel` | — | — | позже, отдельно |

- `vn` больше не используется. `novel` в контенте, пока режим не сделан, — ошибка «режим не реализован» (Р0).

### Обычный режим

- У персонажа — аватары эмоций. У каждой реплики своя эмоция (`emotion`); не указана — `default`.
  Эмоции объявляются у персонажа в контенте; неизвестная эмоция, отсутствие `default`, расхождение списка с картинками — ошибка.
- Имя говорящего не показывается. Реплика — в комиксном облаке с хвостиком, облако по длине фразы (мин./макс. ширина, перенос).
- Облако стоит со стороны взгляда говорящего; у края экрана сдвигается внутрь, на другую сторону не перескакивает.
- Аватар и низ облака — на одной линии; линия своя у каждой локации (`LocationRoot`).
- Аватар смотрит туда же, куда фигура (`Walker.Facing`). Исходники — лицом вправо, нарисованные влево отзеркаливаются при подготовке.
- Текст печатается по буквам; клик во время печати показывает фразу целиком, следующий — следующая реплика. Значка «дальше» нет.
- Звук печати («бормотание») — отдельная задача, позже.

### Аватары

- Папка на персонажа, внутри `emotions/<эмоция>.png` (`default`, `smirk`, …).
- Общий словарь эмоций — `Content/emotions.json`: `emotion.<имя>` и русское название. Имя — это имя файла. Персонаж перечисляет в контенте (`"emotions"`) только эмоции словаря; эмоция не из словаря — ошибка. Стартовый набор — 20 эмоций; какие обязательны, решим позже.
- Аватар — картинка в экранных пикселях, а не pixel art на сетке мира (2026-11-11; закрывает О-03 стандарта для портретов):
  исходники из генератора — иллюстрации без сетки «псевдопикселей», при сведении к сетке черты лица пропадают.
  В игре один пиксель картинки — один пиксель Full HD; Unity только подгоняет под разрешение экрана (сглаживание с mipmaps).
- Все аватары всех персонажей — одного размера в игре (2026-11-11): ровно 115×135 пикселей Full HD, половина стандартного выреза карточки 229×270
  (голова и плечи, как на карточках героя); размер тестовый. Исходник другого кадрирования или меньше аватара — ошибка; заглушки подгоняются отдельно.
  Уменьшает скрипт `tools/art/prepare-avatars.ps1` заранее (Ланцош в линейном свете), исходник не трогается: сменить размер — перезапустить скрипт.
- Исходники персонажа — файлы `<эмоция>.png` прямо в папке художника (`characters.json`, `avatars.source`); подпапки — его архив, скрипт их не читает.
- У эмоции будут состояния «говорит» и «слушает»; короткие анимации (3–5 кадров) — по кругу. Сделаем, когда понадобятся сценам.
- Облако и аватар стоят рядом нижним краем на линии локации, промежуток между ними — над говорящим (2026-11-11):
  облако со стороны взгляда, хвостиком к говорящему; аватар — за его головой. У края экрана сдвигаются внутрь вместе. Линия — одной высоты во всех локациях (282 пикселя сетки от низа экрана); у отдельного экрана правится, если его картинке нужно.

### Монолог

- Мысли героя вслух, реплики NPC «в воздух». Только облако, без аватара. Облако — тоже комиксное, по длине фразы.
  Мысль героя — то же облако, но вместо хвостика под ним след из двух кружков к голове (2026-11-11). Реплика NPC в воздух — облако с хвостиком, как в разговоре.
  Облако держится над точкой ног говорящего на высоте головы, измеренной при показе фразы: кадры ходьбы и разворот его не трясут.
- Срабатывает с любой дистанции (клик по персонажу — разговор, ПКМ по предмету — мысль героя); герой не останавливается и не идёт к цели.
- Одна фраза за клик. Облако гаснет через 7 с (2026-11-11; было 11 с) или по следующему клику по той же цели, который показывает следующую фразу.
  Время — настройка игрока (экран настроек позже; сейчас — `DialogueView.MonologueSeconds`).
- ПКМ по пустому месту двигает мысль героя: показанная мысль переходит к следующей заготовленной фразе, а если её нет — облако закрывается.
  Заглушки так не листаются: после заглушки ПКМ по пустому месту закрывает облако.
  Таймер только скрывает облако: следующий клик продолжает с того же места, монолог не начинается заново.
- Облаков может быть несколько — по одному на говорящего. Новая фраза того же говорящего заменяет его облако.
- Выход из локации убирает все облака (техническая отмена, 0.3 §2.4).
- Сцена может запустить монолог (мысль героя, реплику NPC или предмета), но не ждёт его: фраза появилась —
  сцена сразу идёт дальше и управление не держит. Строгий порядок «договорил, потом произошло» — только обычный режим.
- Говорить монологом может и предмет («дверь проговаривает своё событие») — в облаке другого вида; пока не нужно.

**Что говорит цель по клику** (если под действие нет сцены — сцены приоритетнее, Р6):

1. **Заготовленный монолог** — упорядоченные фразы, привязанные условием к моменту игры. Идут строго по порядку,
   каждая один раз; прогресс сохраняется в сохранении.
2. Заготовленные кончились — **заглушки**: абстрактные фразы по кругу. Свой пул у персонажа или предмета; у кого своего нет — общий пул.
   Общий пул сейчас — одна фраза «Мне нечего тебе сказать».
3. В конце круга заглушек система показывает «…»: игрок понимает, что услышал всё. «…» не пишется в контенте.

Пример: заготовлено «Опять ты.», «Говорят, о тебе спрашивали.»; свой пул — «Наливать?», «Сегодня тихо.».

> клик → «Опять ты.» · клик → «Говорят, о тебе спрашивали.» · клик → «Наливать?» · клик → «Сегодня тихо.» · клик → «…» · клик → «Наливать?» …

У NPC без своих фраз: «Мне нечего тебе сказать.» → «…» → «Мне нечего тебе сказать.» → …

**Демо-контент:** «Опять этот офис.» — монолог героя из сцены первого входа в офис (`location_entered` + `repeat: once`).
«Замок щёлкнул. Дверь открыта.» убирается: открытие показывают исчезнувший ключ и звук щелчка.

**Меняет Р6:** пул generic — у цели, а не общий на тип действия; пул из одной фразы допустим (повтор подряд разделяет «…»).

## Р11. Радиус взаимодействия героя (2026-11-11; отменяет T13 — автоматический подход)

- Игрок водит героя сам; по клику герой никуда не идёт.
- ЛКМ по предмету, объекту или NPC срабатывает, только если цель в радиусе героя: от середины героя до ближнего края нарисованной цели —
  не больше `HeroController.InteractionRadius` (108 пикселей сетки; было 120). Цель дальше — ничего не происходит (не ошибка).
- ПКМ (осмотр, мысль героя) работает с любого расстояния.
- Если действие запускает сцену, герой сразу останавливается на месте и поворачивается к цели, персонаж — к нему. Монолог героя не останавливает.
- Точка подхода у представления остаётся только для сцен: действие `move` ведёт персонажа к ней.

Пример: Параноик стоит у окна, дверь в другом конце офиса. ЛКМ по двери — ничего. Игрок ведёт героя к двери; когда до неё 108 пикселей и меньше, ЛКМ — «Заперто.» ПКМ по двери из любого места — мысль о ней.

## Р12. Выборы в диалоге и режим новеллы (2026-11-13; описание, не реализовано)

Статус: описание принято (2026-11-13), часть пунктов открыта (ниже). Сделано (2026-11-13): выборы в обоих режимах,
ветки, переход варианта в другой диалог, экран новеллы (размытый «сонный» фон локации, изображение собеседника,
панель с именем, мягкое появление). Не сделано: исход новеллы и переходы выхода по нему, музыка, эмоции новеллы кроме
`default` у первого персонажа, мини-игры.

**Формат в контенте.** Шаг диалога — реплика или выбор `{ "choice": [ варианты ] }` (2–9 вариантов, по клавише на каждый).
Вариант: `label` — что видит игрок; `lines` — реплики ветки (могут быть пусты и содержать свои выборы); затем одно из:
ничего — продолжить диалог после выбора; `"end": true` — закончить разговор; `"next": "dialogue.x"` — продолжить в
другом диалоге (например, в новелле). Новелла: `"mode": "novel"`, `"partner": "character.x"`; говорят только герой и
собеседник; у говорящих в новелле есть имя. Изображения новеллы — 630×880, `tools/art/prepare-avatars.ps1 -Kind novel`
(исходник на зелёном фоне — `"key": "green"`).

### Выборы (обычный режим и новелла)

- В диалоге может быть выбор ответа героя. Варианты показываются пронумерованными, название — в квадратных скобках:
  `1. [Согласиться]`, `2. [Уйти]`. В обычном режиме — в облаке, в новелле — в нижней панели.
- Выбор — мышью по варианту или клавишей с цифрой (1, 2, 3 …). Выбирается ровно один вариант, вернуться нельзя.
- Игрок видит только название варианта, а не то, что скажет герой. Вариант ведёт в ветку: несколько реплик героя и NPC.
  Пример: `1. [Да]` → герой: «Да, я давно хотел этого.» → NPC отвечает.
- Выбор пока ни на что не влияет за пределами диалога: он не запоминается в State и не сохраняется.
- Вариант может вести в новеллу. Пример: в баре девушка (обычный режим): «Хочешь узнать друг друга лучше?» →
  `1. [Да]` — переход в новеллу; `2. [Мне пора]` — разговор закрывается.

### Новелла (`novel`)

Назначение — романтичные разговоры с NPC. Это расширенный обычный диалог.

- **Экран.** Объекты локации скрываются (персонажи, предметы, герой); остаётся фон локации с эффектами «как во сне»:
  лёгкое размытие и чуть больше красочности. Мы будто смотрим глазами героя на собеседника, фокус — на нём.
- **Собеседник.** В центре экрана — крупное детализированное изображение NPC (около 630×880 пикселей Full HD), фон
  изображения прозрачный. Свой стиль изображений новеллы: персонаж узнаваем, но детальнее и привлекательнее — стиль
  фиксируется в визуальном стандарте.
- **Изображения — эмоции.** У персонажа 3–5 изображений новеллы; каждое привязано к эмоции, реплика NPC задаёт эмоцию.
  По реакциям NPC игрок в будущем сможет следить за своим продвижением в разговоре.
- **Панель.** Реплики — внизу, в отдельной полупрозрачной стилизованной панели; имя говорящего показывается.
  Там же — варианты ответа.
- **Течение.** Только по нажатию игрока: автопроигрывания нет, назад вернуться нельзя.
- **Мир.** Стоит. Сохраняться посреди новеллы нельзя.
- **Запуск.** Сама — после определённых действий игрока (сцена), или по действию игрока, например по варианту ответа в
  обычном диалоге.
- **Музыка.** Свои музыкальные композиции новеллы.
- **Переходы.** Вход — «сказочный» переход; выход — переход, зависящий от того, чем кончилась новелла.
- **Позже.** Мини-игры внутри новеллы.

Пример: герой в баре говорит с девушкой в обычном режиме. Она предлагает «узнать друг друга лучше»; игрок выбирает
`1. [Да]`, герой отвечает, и вместо следующей реплики — сказочный переход. Фон бара размыт и ярче, все фигуры исчезли,
в центре — она, крупно. Внизу панель: её реплика с именем, затем варианты ответа. Игрок выбирает, герой говорит свою
фразу, она отвечает, её изображение меняется по эмоции. В конце — переход обратно в бар, его вид зависит от исхода.

### Уточнения (предложены мной, приняты 2026-11-13)

- **Где варианты в обычном режиме:** в облаке героя, рядом с его аватаром (выбирает герой).
- **Ветки:** после своих реплик ветка возвращается к общему продолжению разговора, если не кончает его сама.
- **Вариант → новелла:** ветка кончается переходом в другой диалог (новеллу) — разговор продолжается без возврата
  в мир, между ними играет переход входа.
- **Исход новеллы** — принято, но **не реализуем сейчас**, пользователь опишет подробнее: автор помечает конец каждой
  ветки новеллы исходом (например, «тепло», «неловко»), исход выбирает переход выхода и нигде не запоминается.
- **Изображения новеллы:** эмоции — из того же словаря, что у аватаров (`Content/emotions.json`); файлы —
  `Art/Characters/<имя>/novel/<эмоция>.png`, прозрачный фон, в экранных пикселях (не на сетке мира).
  Стиль и детализация **не решены**: изображения не обязаны быть пиксельными — стиль ещё нужно выяснить и
  зафиксировать в визуальном стандарте.
- **Что остаётся от локации:** задник и дальние планы (`ParallaxLayer` с долей 0..1); ближний план скрывается вместе
  с объектами.
